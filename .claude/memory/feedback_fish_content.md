# 魚種ページ固定文（fish_content）執筆ルール

ユーザー確定 2026/06/11。

1. 文章は「固定/月1更新パート」と「日次自動更新パート」に分離する。
2. 数値はすべて自サイトB層データ（data/V2 CSV集計）から差し込む。出典明記不要。
3. **定性記述（系統B＝ドメイン知識由来）は必ず外部サイトで裏取りしてから採用する。**
   - WebSearch で2ソース以上確認。確認できない表現（通称・「標準」断定等）は落とすか弱める。
   - 文章はコピペ禁止・完全に独自文に書き直す。出典はページに表示しない（内部記録のみ）。
4. 自前データと外部定説が食い違う場合は自前データ優先で表現を分岐させる
   （例: マルイカ出船時間帯は三浦・葉山=日中 / 沼津・鹿島=夜便中心、と time_slot 集計で判明）。
5. **執筆前にエリア別分解チェック必須**（月別件数・水深・サイズ・time_slot をエリアグループ別に集計）。
   タックル・シーズン・サイズがエリアで異なる場合は省略せず書き分ける
   （例: マルイカは三浦=春〜初夏・日中多点スッテ / 沼津=冬+真夏・夜イカメタル / 鹿島=夏半夜・型40cm）。
6. emoji は Unicode でなく既存の魚種別画像 `assets/fish/{slug}/{slug}_emoji.webp` を使う。
7. 月報が実在する魚種のみシーズン解説末尾に最新月報リンク（空リンク・「準備中」は出さない）。

## 2026-09-05: 月1再生成が3か月止まっていた（原因と再発防止）

`fish_content_stats.json` が `generated: 2026-06-12` のまま3か月放置され、
固定文の数値が実データより **12〜24% 過小**になっていた（アジ 18,826→23,000 等）。

**止まっていた理由**: 再生成すると 70魚種中52で文中の値が変わり、**21魚種で文章が矛盾する**。
「順序非依存の文型で書く」という教訓は**実際には守られていなかった**。壊れ方は2種類:

1. **差し込み月とハードコードした季節が同格** — 「{month_top1}・9月の秋が最盛」で
   top1 が 4月 になると「4月・9月の秋が最盛」。オニカサゴ「{month_top1}・12月・2月の冬に
   最大の山」で top1 が 5月 になるのも同型
2. **差し込みポイント名とハードコードした地理が同格** — シロギス「神奈川側の{point1}と
   千葉側の{point2}」で point1 が木更津沖（千葉）になると地理が逆。
   ハナダイ「{point2}など九十九里」で point2 が下浦沖（三浦）になるのも同型

**直し方（2026-09-05 に21魚種へ適用）**: 差し込み値を**独立した文**にする。
「データ上の最多は{month_top1}（{month_top1_n}便）。」で切り、季節・地理の断定は次の文へ。
こうすると値がどう動いても文が壊れない。

**ついでに見つかったこと**: 元の季節記述そのものがデータとずれていた魚種があった。
シーバスは「10〜12月の秋〜初冬がピーク」と書いてあったが、実データは 4月180便・3月164便で
**春が最多**。オニカサゴの「冬に最大の山」も 5月114便が最多で誤り。
ルール4（自前データと外部定説が食い違う場合は自前データ優先）に沿って書き換えた。

**次回の運用**: 再生成の前に必ず
`month_top1 / month_top2 / month_low / point1-3 / area1-3` の変化と、
その値を文中で使っている魚種を突き合わせる。上の2パターンに当てはまる文が残っていないか見る。

- 執筆時の教訓:
  - validate は **パイプ無しで exit code を直接確認**（tail にパイプすると失敗が握り潰される）
  - 800字ゲートは初稿で 850字以上を目安に書く（リンクタグ除去後の字数で判定される）
  - プレースホルダは順序非依存の文型で（month_top1 が想定外の月でも文意が壊れない形）
