# 実釣・取材レポートの書き方（field_reports.json）

**これは AdSense 診断で NG だった「Experience（体験・経験）」を埋める唯一の経路。**
自動収集データをどれだけ磨いても、この項目は動かない。

---

## なぜ必要か

2026/07/27 の AdSense 診断結果:

| カテゴリ | 判定 |
|---|---|
| A サイト構造 / B コンテンツポリシー / D スパム | **全 OK** |
| C-3 Trustworthiness | OK |
| **C-1 Experience** | **NG** ← ここ |
| **C-2 Expertise** | **NG** ← ここ |
| C-4 コンテンツ品質 | NG（2026/07/27 に分析セクション拡張で対応済み） |

指摘の要点:

> 著者自身の実釣体験、テストフィッシング、現地調査に基づく記述がなく、
> 釣果データベースから集計した統計情報と船宿情報の提供に限定されています。

つまり **「行った人が書いた文章が1本もない」** ことが問題。

---

## 書くもの / 書かないもの

| 書く | 書かない |
|---|---|
| 実際に乗った船・日付・釣れた数と型 | 「一般に〜と言われています」 |
| 自分が試した仕掛け・タナ・誘い方と、その結果 | 他サイトや YouTube の受け売り |
| **うまくいかなかったこと**（ボウズ・オマツリ・船酔い） | 行ってないのに書く推測 |
| 船宿の人に直接聞いた話（誰にいつ聞いたか明記） | 匿名の伝聞 |
| 港へのアクセスで実際に困ったこと | 地図を見ただけの説明 |

**失敗を書くほど一次体験の証拠になる。** きれいな成功譚だけだと逆に疑われる。

---

## 分量と本数の目安

- 1本 **400〜800字** で十分。長文である必要はない
- **まず3〜5本**。全ページに要らない。データが厚い代表ページから
- 推奨の初手: `フグ|鹿島港` / `マダイ|飯岡港` / `タイ五目|茅ヶ崎港`
  （いずれも便数が多く、分析セクションも厚いページ）

## 書き方（`normalize/field_reports.json` の `reports` に追記）

```json
"reports": {
  "フグ|鹿島港": [
    {
      "author": "（About ページと同じ表記）",
      "type": "実釣",
      "date": "2026-10-18",
      "ship": "幸栄丸",
      "title": "10月中旬の鹿島でカットウを試した記録",
      "html": "<p>朝5時半出船。……</p><p>結果は……</p>",
      "takeaways": [
        "読者が次に使える学びを1行で",
        "3個まで"
      ]
    }
  ]
}
```

| フィールド | 必須 | 備考 |
|---|---|---|
| `author` | ✅ | 無いとレンダリングされない（出典を示せないものは出さない仕様） |
| `date` | ✅ | 同上。実際に行った日 |
| `type` | — | `実釣` / `取材` / `現地調査` |
| `ship` | — | 乗った船宿・取材先 |
| `title` | — | 無くても可 |
| `html` | ✅ | `<p>` で段落分け |
| `takeaways` | — | 最大3個 |

キーは fish_area ページと同じ `魚種|エリア` 形式。同じキーに複数本を配列で入れられる。

## 反映のされ方

`crawler.py _build_field_report_section` が fish_area ページの
「海況と釣期の傾向（データ分析）」の直後に描画する。
自動集計と混ざらないよう、種別バッジ・執筆者・実施日を必ず表示する。

反映は **日次 crawl（16:30 JST）** のタイミング。ローカルで `crawler.py` を
フル実行する必要はない（HERO 日付が巻き戻るため非推奨）。

## 港・船宿のことを書くときのルール（2026-07-27 追加）

港や船宿の話は、**「事実」と「体験」を分ける**。混ぜると危ない。

| | 例 | 扱い |
|---|---|---|
| **事実** | 駐車場は無料で30台／受付は6時から／レンタル竿あり | **記憶で書かない**。変わるし、間違うと読者が実害を受ける（違う時間に行く・停められない）。公式サイトへのリンクで「最新は公式で確認」に寄せる |
| **体験** | 5時に着いたら半分埋まっていた／受付が漁協の2階にあると分かるまで手前でうろうろした／氷は途中のコンビニで買った | **書ける**。「その日そうだった」以上のことを主張していないので、後で状況が変わっても嘘にならない |

判別のしかた: **「今もそうですか？」と聞かれて困るなら事実、困らないなら体験。**
「駐車場は30台」は今も30台か保証できないので事実。
「自分が行った日は5時で半分埋まっていた」は、その日の話なので変わりようがない。

書くときは必ず**いつの話かを添える**（`date` フィールド、または本文中に「2026年◯月に行ったときは」）。

そして near-duplicate 対策として効くのは**体験のほう**。
「◯◯港の駐車場は無料」はどのサイトにも同じ文があるので、むしろ重複判定を招く。

参考: 船宿の**料金は crawler.py のサニタイザで一切出さない方針**（変動するため・crawler.py の
料金表記サニタイザ）。同じ考え方を駐車場・受付時間にも適用する。

## 注意

- **書いていないことを書かない。** ここが崩れると、データ部分の信頼まで一緒に落ちる
- **うろ覚えの魚名・地名は、うろ覚えのまま渡してよい。** `data/V2` の記録から引ける
  （例: アマダイの「なんとかカレイ」→ ムシガレイ 約310件と特定できた）。
  ただし科を取り違えると検索も外すので、「カレイ系」「メバル系」程度の手がかりがあると確実
- 写真を載せる場合は**自分で撮ったものだけ**（他所の画像の借用は AdSense でマイナス）
- 船宿取材は先方の許可を取ってから。名前を出す場合は特に
